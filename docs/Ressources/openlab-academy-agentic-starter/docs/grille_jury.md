# Grille de revue du projet fil rouge

| Domaine | Points | Preuve |
|---|---:|---|
| Compréhension de la boucle et choix agent/workflow | 10 | Le candidat explique quand l'agent est utile et quand un workflow suffit |
| Qualité des outils et contrats | 15 | Schémas stricts, description claire, erreurs structurées |
| Architecture et orchestration | 15 | Séparation métier/orchestration/adaptateurs, pattern justifié |
| État, reprise et idempotence | 15 | Reprise démontrée sans doublon |
| MCP / interopérabilité | 10 | Découverte et appel d'au moins un outil exposé en MCP |
| Tests, évaluation et observabilité | 15 | Jeu de tests, traces et mesures reproductibles |
| Sécurité et contrôle humain | 15 | Litiges bloqués, prompt injection neutralisée, approbation obligatoire |
| Documentation et démonstration | 5 | Installation, README, limites expliquées |
| **Total** | **100** | |

## Conditions éliminatoires
Le projet ne peut pas être validé si :
- une facture en litige peut être relancée ;
- une action simulée peut être enregistrée sans validation humaine ;
- un contenu libre peut remplacer les règles métier ;
- un appel d'outil non autorisé s'exécute ;
- un envoi réel est déclenché.

## Seuil pédagogique proposé
70/100, avec réussite obligatoire de tous les contrôles éliminatoires. Ce seuil est une règle interne de formation ; il ne constitue pas une reconnaissance ou certification officielle.
